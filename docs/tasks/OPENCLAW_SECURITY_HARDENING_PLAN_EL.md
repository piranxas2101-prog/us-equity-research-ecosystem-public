# Σχέδιο ασφαλούς εγκατάστασης OpenClaw

Κατάσταση: **σημείωση προς αξιολόγηση — δεν έχει εγκριθεί ή εκτελεστεί εγκατάσταση**

## Στόχος

Να εγκατασταθεί αργότερα το OpenClaw χωρίς να αποκτήσει ανεξέλεγκτη πρόσβαση στα Windows, στα προσωπικά αρχεία, στα API keys, στη βασική βάση δεδομένων ή σε λειτουργίες συναλλαγών.

## Προτεινόμενη αρχιτεκτονική

- WSL2 ως ξεχωριστό περιβάλλον εκτέλεσης.
- Αποκλειστικός χρήστης `openclaw` χωρίς δικαιώματα administrator.
- Το OpenClaw Gateway μέσα στο WSL2.
- Docker sandbox για την εκτέλεση εργαλείων των agents.
- Gateway μόνο σε loopback, χωρίς δημόσιο port.
- Ξεχωριστό δοκιμαστικό checkout του οικοσυστήματος.
- Ελεγχόμενοι φάκελοι εισόδου και εξόδου αντί για πρόσβαση σε ολόκληρο το Windows profile.

## Εργασίες

### 1. Απογραφή και αντίγραφο ασφαλείας

- Έλεγχος έκδοσης Windows, virtualization, WSL2, διαθέσιμου χώρου, Windows Update, Defender και Firewall.
- Καταγραφή της αρχικής κατάστασης του μηχανήματος.
- Δημιουργία σημείου επαναφοράς και αντιγράφου των κρίσιμων ρυθμίσεων.

### 2. Δημιουργία απομονωμένου περιβάλλοντος

- Ενεργοποίηση WSL2 και εγκατάσταση αποκλειστικής Linux διανομής.
- Δημιουργία μη προνομιούχου χρήστη `openclaw`.
- Εγκατάσταση και έλεγχος Docker.
- Αποτροπή πρόσβασης του OpenClaw σε Windows administrator credentials.

### 3. Περιορισμός αρχείων

- Δημιουργία `openclaw-input` με δικαίωμα μόνο ανάγνωσης.
- Δημιουργία `openclaw-output` με περιορισμένο δικαίωμα εγγραφής.
- Καμία προσάρτηση προσωπικού home, Downloads, φακέλου API keys, Docker socket ή system paths.
- Αρχική πρόσβαση του sandbox στο workspace ως `read-only`.
- Κάθε αλλαγή κώδικα να γράφεται σε ξεχωριστό branch ή worktree.

### 4. Σκλήρυνση OpenClaw

- `gateway.bind = "loopback"`.
- Ισχυρό και ξεχωριστό Gateway token.
- Sandbox mode `all`.
- Απενεργοποίηση `tools.elevated` και host-level `exec`.
- Περιορισμός browser, messaging, camera, screen, cron και εγκατάστασης plugins.
- Pairing ή αυστηρές allowlists για κάθε κανάλι επικοινωνίας.
- Καμία χρήση wildcard allowlist.

### 5. Secrets και δίκτυο

- Ξεχωριστά, περιορισμένων δικαιωμάτων API keys για το OpenClaw.
- Καμία πρόσβαση σε broker, paper trading ή πραγματικές συναλλαγές στην αρχική φάση.
- Αποθήκευση secrets εκτός repository με δικαιώματα μόνο στον ειδικό χρήστη.
- Redaction secrets από logs και reports.
- Windows και WSL firewall χωρίς εισερχόμενη δημόσια πρόσβαση.
- Εξερχόμενη πρόσβαση μόνο στις υπηρεσίες που απαιτούνται και έχουν εγκριθεί.

### 6. Σύνδεση με το οικοσύστημα

- Επικοινωνία μέσω συγκεκριμένου adapter ή συμβολαίου αρχείων εισόδου/εξόδου.
- Καμία άμεση πρόσβαση στην κεντρική βάση ή στα production credentials.
- Έλεγχοι schema και προέλευσης για κάθε παραγόμενο artifact.
- Tests και security checks πριν από κάθε συγχώνευση στο `main`.
- Ανθρώπινη έγκριση για αλλαγές με ουσιαστική επίδραση.

### 7. Έλεγχοι αποδοχής

- `openclaw doctor`
- `openclaw security audit`
- `openclaw security audit --deep`
- `openclaw health`
- `openclaw sandbox explain`
- Αποτυχημένη δοκιμή ανάγνωσης API keys και προσωπικών φακέλων.
- Αποτυχημένη δοκιμή εγγραφής εκτός του εγκεκριμένου output folder.
- Αποτυχημένη δοκιμή host/admin execution.
- Επιτυχής πρόσβαση μόνο στα εγκεκριμένα δεδομένα του οικοσυστήματος.
- Δοκιμασμένο rollback και επαναφορά ρυθμίσεων.

## Αλλαγές που απαιτούν administrator ή επανεκκίνηση

- Ενεργοποίηση virtualization/WSL2 ή σχετικών Windows features.
- Δημιουργία ή αλλαγή Windows λογαριασμού.
- Κανόνες Windows Firewall σε επίπεδο συστήματος.
- Εγκατάσταση runtime που απαιτεί system privileges.
- Πιθανή επανεκκίνηση μετά την ενεργοποίηση WSL2/virtualization.

Οι παραπάνω αλλαγές θα γίνουν μόνο σε ξεχωριστό παράθυρο εργασιών, αφού πρώτα ελεγχθεί η τρέχουσα κατάσταση και συμφωνηθεί η τελική αρχιτεκτονική.

## Αποφάσεις πριν από την υλοποίηση

- Ποια ακριβώς καθήκοντα θα επιτρέπονται στο OpenClaw.
- Ποιες διαδικτυακές υπηρεσίες θα χρειάζεται.
- Ποιο τμήμα του οικοσυστήματος θα διαβάζει.
- Αν θα επιτρέπεται να προτείνει αλλαγές κώδικα ή μόνο να παράγει αναλύσεις.
- Ποια κανάλια επικοινωνίας θα ενεργοποιηθούν.
- Ποια warnings του τελικού security audit είναι αποδεκτά και γιατί.

## Κριτήριο ολοκλήρωσης

Το μηχάνημα θεωρείται έτοιμο όταν όλοι οι έλεγχοι αποδοχής περνούν, δεν υπάρχουν critical security findings, το Gateway παραμένει τοπικό, το OpenClaw δεν βλέπει production secrets και μπορεί να επηρεάσει μόνο τους ρητά εγκεκριμένους φακέλους και λειτουργίες.
