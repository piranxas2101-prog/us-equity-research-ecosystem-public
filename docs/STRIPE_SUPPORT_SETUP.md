# Stripe support setup

This is the maintainer checklist for adding an optional support link to the repository. Do not activate it before the ecosystem and downstream agents have passed end-to-end review and the public release is ready. It is not active until a real, verified link replaces the status text in [Support the project](../DONATIONS.md).

1. **Confirm the payment description and account eligibility.** Stripe distinguishes tips for work already provided from donations tied to a specific charitable purpose. This project currently presents voluntary support for published research software and educational content; do not describe it as a charitable or tax-deductible donation without the appropriate basis. Review [Stripe's tips and donations requirements](https://support.stripe.com/questions/requirements-for-accepting-tips-or-donations) and any applicable account or local obligations before going live.
2. **Create a Stripe-hosted Payment Link in the Dashboard.** For a one-time flexible amount, choose *Customers choose what to pay* and give the page a clear title and description of what support funds. Stripe also supports fixed-amount one-time or recurring links. Choose the call to action that fits the approved payment description. See [Stripe's Payment Links support guide](https://support.stripe.com/questions/how-to-accept-donations-through-stripe?locale=en-GB).
3. **Check the link in the intended mode.** Verify the title, amount options, currency, branding, confirmation text and account owner in Stripe before publishing. Keep payment and card details on Stripe's hosted page. The repository needs only the public Payment Link URL; no Stripe secret key, webhook or custom checkout is required for this simple support flow.
4. **Publish one verified live URL.** Add it to `DONATIONS.md`. To display GitHub's Sponsor button, add `.github/FUNDING.yml` with `custom: "https://..."` on the default branch, then check the link from the repository page. GitHub documents the [custom funding URL and default-branch requirement](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/displaying-a-sponsor-button-in-your-repository).

Do not add a placeholder `FUNDING.yml`: GitHub would present a broken payment destination. The active support page should say what contributions fund and should never imply that paying changes research results or unlocks broker access.
