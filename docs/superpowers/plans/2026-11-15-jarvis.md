# Jarvis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Jarvis, the ecosystem's own operator: after the nightly run and the afternoon session it checks health,
runs the due checks, learns loss rules from the paper ledger, turns findings into proposals, writes one daily report,
and lets the owner read it, decide proposals and chat with it on a Control Center page.

**Architecture:** Deterministic Python modules `jarvis_*.py` at the repo root, called by the existing launchers at
their ends (no new scheduled task). State in `data/jarvis/` (SQLite), reports in `output/jarvis/`. Learned rules go into
the existing learning store as shadow lessons. The chat is a read-only local-Ollama layer over Jarvis's files. The
Control Center gets a "Jarvis" page through its existing token/Origin/JSON action path.

**Tech Stack:** Python 3.12 (`.venv-next`), sqlite3, scikit-learn 1.9.1 / numpy / pandas (already in the lock),
urllib to local Ollama, Windows PowerShell 5.1 launchers, vanilla JS page.

**Spec:** `docs/superpowers/specs/2026-11-15-jarvis-design.md`

## Global Constraints

- Test runner: `.\.venv-next\Scripts\python.exe -m unittest tests.test_<module>`; tests are deterministic, no network,
  no real Ollama, no real `data/` or `output/` (use `tempfile` roots).
- No `jarvis_*.py` module may import (directly or through a module it imports) `alpaca_*`, `paper_trade_ledger`,
  `thymios_order_intent`, `koulis_risk_gate`, `start_trader_*`, or any order/broker code. Read the ledger with
  `sqlite3` directly.
- Jarvis never starts a research run, resumes one, starts a trading session, starts the Ollama app, or changes any
  score, policy, threshold, risk limit, playbook, lesson status or model state. The only learning-store write is
  `agent_learning_control_plane.upsert_lesson_candidate` (which puts a new lesson straight into shadow).
- Unknown stays unknown: a missing file/field is reported as `unknown` with the reason, never as zero or ok.
- Time budget per pass: `JARVIS_BUDGET_SECONDS = 600` (10 minutes). Long producers only on the Saturday nightly pass.
- Paths: state `data/jarvis/proposals.sqlite3`, `data/jarvis/chat.sqlite3`, `data/jarvis/pass_state.json`; reports
  `output/jarvis/report_<YYYY-MM-DD>.md|.json` and `report_latest.md|.json`; registry `jarvis_checks.json` (committed);
  config `jarvis_config.json` (committed).
- Report and page text in Greek (the owner's language); PowerShell lines ASCII only (`test_unattended_scripts_are_ascii`).
- Proposal "Later" re-asks after `LATER_SESSIONS = 5` sessions.
- New dependencies: none.
- Commit after each task, then (owner's standing instruction) at the end push to `main` and run
  `.\.venv-next\Scripts\python.exe publish_public.py --push`; run the `invariants` skill before the push.

## Review Focus

1. First ever pass with empty `data/jarvis/`, no ledger DB, no evaluation file: every section says `unknown`/"not
   enough data", the report is still written. (Task 5 test `test_first_pass_with_nothing_writes_report`.)
2. The same pass run twice on one day (launcher retry, manual rerun): no duplicate proposals, the report is
   overwritten, not appended. (Task 1 `test_upsert_is_idempotent`, Task 5 `test_second_pass_same_day_is_idempotent`.)
3. Ollama not running / model missing: the chat answers with a plain "Ollama is not running" message and HTTP 200,
   never a 500, never an attempt to start it. (Task 7 `test_ollama_down_gives_plain_message`.)
4. A producer that hangs or exceeds the budget: it is killed at its timeout, the check is `timeout`, the pass goes on.
   (Task 3 `test_producer_timeout_is_recorded`.)
5. A Jarvis crash must never stop the launcher's rest/hibernate step. (Task 6 static test: the Jarvis call is inside
   `Invoke-Logged` and its exit code is only logged.)

### Task 1: Proposal store (`jarvis_state.py`)

**Files:**
- Create: `jarvis_state.py`

**Interfaces:**
- Produces:
  - `PROPOSALS_DB = ROOT / "data" / "jarvis" / "proposals.sqlite3"`; `LATER_SESSIONS = 5`
  - `connect(path: Path = PROPOSALS_DB) -> sqlite3.Connection` (creates tables `proposals`, `decisions`)
  - `@dataclass Proposal: source: str` (`"jarvis_learning" | "paper_learning" | "check"`), `source_key: str`
    (lesson_id or check id), `title: str` (Greek, one line), `evidence: dict` (numbers + file paths),
    `change: str` (what would change), `rules_review: str | None`
  - `upsert_proposal(conn, p: Proposal, *, session_date: str) -> tuple[str, str]` returns `(proposal_id, action)` with
    action in `"created" | "updated" | "unchanged" | "suppressed"`. `proposal_id = "prop_" + sha256(source|source_key)[:16]`.
    Evidence is "materially changed" when `evidence_fingerprint(evidence)` differs; fingerprint = sha256 of
    `evidence["verdict"]` plus every numeric value rounded to 1 decimal.
  - `decide(conn, proposal_id: str, decision: str, *, note: str, session_date: str) -> dict` with decision in
    `"yes" | "no" | "later"`; raises `ValueError` otherwise or for an unknown id.
  - `open_proposals(conn, *, session_date: str, sessions_since: Callable[[str], int]) -> list[dict]`: state `open`, or
    `later` whose decision is `LATER_SESSIONS` or more sessions old.

### Task 4: Learning loss rules (`jarvis_learning.py`)

**Files:**
- Create: `jarvis_learning.py`
- Test: `tests/test_jarvis_learning.py`

**Interfaces:**
- Consumes: `jarvis_state.Proposal`.
- Produces:
  - Constants (starting values, documented in the module docstring as Claude's call, to be revisited with the
    first real numbers): `MIN_SESSIONS = 10`, `TRAIN_SHARE = 0.7`, `MAX_DEPTH = 3`, `MIN_LEAF = 10`,
    `TRAIN_LOSS_RATE = 0.65`, `TEST_MIN = 5`, `TEST_LOSS_RATE = 0.60`, `FOLLOW_MIN = 10`, `TASK_ID = "jarvis_learning"`,
    `RUBRIC = "jarvis-learning.v1"`, `FEATURES = ("agent", "playbook", "direction", "holding_class", "market_state",
    "market_state_fit", "standing")` (`standing` = `categories.standing`).
  - `load_trades(db_path: Path) -> list[dict]` - `SELECT record_json FROM paper_trade_ledger WHERE kind='trade'`;
    keeps records with a numeric `result_pct`; a missing feature value becomes the string `"unknown"`.
  - `find_rules(trades: list[dict]) -> dict` → `{"status": "not_enough_data" | "ok", "sessions": int,
    "train_sessions": [first, last], "test_sessions": [first, last], "rules": [Rule]}` where a Rule is
    `{"criterion_id": "jarvis_loss_rule:" + "|".join(sorted("k=v")), "conditions": {k: v}, "train": {"n", "losses",
    "loss_rate_pct"}, "test": {...}}`. Split by session date (oldest `TRAIN_SHARE` of distinct sessions train).
    `DecisionTreeClassifier(max_depth=MAX_DEPTH, min_samples_leaf=MIN_LEAF, class_weight="balanced", random_state=0)`
    on one-hot features, target `result_pct < 0`. Each leaf's path gives equality conditions (`k=v` from positive
    one-hot splits; negative splits are dropped, so the rule is the leaf's positive conditions); keep a rule when its
    train loss rate ≥ `TRAIN_LOSS_RATE` with n ≥ `MIN_LEAF` and its test subset has n ≥ `TEST_MIN` and loss rate ≥
    `TEST_LOSS_RATE`. Rules with no positive condition are dropped.
  - `record_rules(intel_db: Path, rules: list[dict]) -> list[dict]` - for each rule
    `agent_learning_control_plane.upsert_lesson_candidate(conn, target_agent=conditions.get("agent", "sokratis"),
    task_id=TASK_ID, rubric_version=RUBRIC, criterion_id=..., support_count=train n, proposal={fixed text per
    criterion, "activation": "candidate_only", "changes_active_scores": False, "requires_shadow_validation": True,
    "requires_manual_promotion": True}, evidence={"train": ..., "test": ..., "generated_at": ...})` via
    `market_intel_db.connect` + `init_schema`. Proposal text (fixed, Greek): "Προσοχή στις θέσεις με <conditions>:
    χάνουν συχνότερα (κανόνας του Jarvis, σε shadow)."
  - `follow(intel_db: Path, trades: list[dict]) -> list[dict]` - every `status='shadow' AND task_id='jarvis_learning'`
    lesson, judged on trades with `session_date > shadow_since` (same `_shadow_since` logic as `paper_learning`:
    last decision `to == "shadow"`): n < `FOLLOW_MIN` → `collecting`; loss rate ≥ `TEST_LOSS_RATE` → `confirmed`;
    else `not_confirmed`.
  - `follow_proposal(item: dict) -> Proposal | None` - `confirmed`/`not_confirmed` → Proposal
    (`source="jarvis_learning"`, `source_key=lesson_id`, evidence includes `verdict`).

### Task 5: The pass and the daily report (`jarvis.py`)

**Files:**
- Create: `jarvis.py`, `jarvis_report.py`
- Test: `tests/test_jarvis.py`, `tests/test_jarvis_report.py`

**Interfaces:**
- Consumes: Tasks 1-4 (`nightly_health`, `session_health`, `load_registry`, `is_due`, `run_check`,
  `check_proposal`, `load_trades`, `find_rules`, `record_rules`, `follow`, `follow_proposal`, `upsert_proposal`,
  `open_proposals`).
- Produces:
  - CLI: `python jarvis.py after-nightly | after-session [--root PATH] [--today YYYY-MM-DD]`; exit 0 even when a
    part fails (each part wrapped; a failed part becomes a report line with the exception type and message).
    Prints one ASCII line for the launcher's notice: `JARVIS <n_open_proposals> proposals, <n_problems> problems`.
  - `run_pass(kind: str, *, root: Path, today: date, python: str, clock=time.time) -> dict` - the whole pass, returns
    the pass record. Order: health → due checks (deadline = start + `JARVIS_BUDGET_SECONDS`) → learning (only on
    `after-session`, and on `after-nightly` only when no session ran that day) → proposals → state → report.
    `is_saturday_nightly = kind == "after-nightly" and today.weekday() == 5`. The session date is New York's date.
  - `sessions_since(root: Path) -> Callable[[str], int]` - distinct `session_date > d` in the ledger (0 when no DB).
  - Paper-learning proposals: from `output/paper_learning/evaluation_latest.json` key `shadow_follow`, items with
    verdict `confirmed`/`not_confirmed` → `Proposal(source="paper_learning", source_key=lesson_id, title=
    proposed_change, evidence={verdict, sessions_after, minimum_sessions, criterion_id})`.
  - Pass state: `data/jarvis/pass_state.json` keeps the nightly pass's sections for the day; the report is written by
    `after-session`, or by `after-nightly` when `today` is Saturday/Sunday or the session log shows no session that
    day. When `after-session` never runs (approval fallback), the next `after-nightly` writes the previous day's
    report first.
  - `jarvis_report.render(pass_record: dict) -> tuple[str, dict]` → (markdown, json). Greek sections, in order:
    "Νυχτερινό run", "Συνεδρία", "Τι πήγε στραβά", "Έλεγχοι", "Τι έμαθα", "Προτάσεις που περιμένουν απόφαση".
    Every unknown is printed as "άγνωστο" with its reason. Written to `output/jarvis/report_<date>.md|.json` and
    copied to `report_latest.*` (overwrite).
